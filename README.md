# Surgical Cleaning Robot ROS2 Migration
Written by Connor McKelvey in collaberation with Daniel Agbara and Heath, HERO Lab Texas Robotics

### A Note
Hi, you probably just cloned this repo or are seconds away from doing so. I know it looks scary with about a billion different config files and random generated files
that even I dont understand, don't panic. Once you have installed ROS2-Jazzy in the workspace and ran pip install for all the necessary modules, getting up and running is 
not as hard as it looks. ROS2 is organized in packages, this project has 2 (although one is just just holding custom service and message types, these can only be declared in a CPP package)
the main package you care about is 'arm_control' it has many nodes that can be launched individually by doing `ros2 run arm_control nodename` however this gets out of hand easily
so I have created 3 relevant launch files: Calibrate, Training, Playback. These can be run using `ros2 launch arm_control calibrate.launch.py` these are an easy way to configure nodes and launch a bunch all at once. the launch files are in the launch folder and are pretty self explainary

### Project structure
arm_control package:
    contains all nodes with names that match the class names and the executable names. 
    if the name includes "driver" it interfaces with a piece of hardware allowing any ros node to interact with it through topics and services
    this system should allow you to keep logic seperate and allows for easy switching between robot arms and such. 
    if the name includes "controller" its a good place to start looking to understand how a launch process works, these nodes often take a bunch of drivers
    and do something with there data, they are also normally responsible for handing user keyboard input
    arm_control/utilities:
        These scripts provide general functionality that nodes use, it keeps the nodes simple. 
arm_control_interfaces package:
    contains custom message types and custom service types for the project located /msg and /srv
    there is no compute or node in this package. if you want to add new types add a line to the CMakeLists.txt
_point_cloud_data folder:
    this folder is used solely by the surface_spill_detection node. when tweaking params or parts of detection algos i wanted to used a saved point cloud. those saved point clouds
    are saved here. the node has a few different modes which are detailed at the top of the node file. this folder is not used in any of the current launch workflows
_training_bags folder:
    when training.lauch.py is launched and a trial is recorded the rosbag folder is generated here. this can be replayed while the playback is running to replicate it.
old_and_tools folder:
    this contains showcase assets, old nodes that are not being used, and helper/plot scripts outside the ros enviroment
cam2base_calibration.yaml file:
    generated by the calibration.launch.py launch workflow. contains the transformation between the camera and the base of the robot. 

### Code standards
I tried to have all nodes have the parameters that you might tweak be ros parameters. these can be tweaked when running nodes individually or in launch files

### Topic List
zed camera topics:
    /camera/tag_pose
    /camera/human_arm_pose
    /camera/image_raw
force sensor topics:
    /force_sensor/data
robot control topics:
    /arm/target_cartesian_pose
    /arm/target_joint_positions
    /arm/current_cartesian_pose
    /arm/current_joint_positions
training visualization topics:
    /training/visualization_markers
training data topics:
    /training/surface_spill_info

### Node List
arm_control package:
    zed_driver.py: interfaces with the zed camera and publishes the relevant topics
    force_sensor_driver.py: interfaces with the force sensor and publishes the relevant topics
    ur_driver.py: interfaces with the urobot lite6 robot arm and publishes the relevant topics
    surface_spill_detection.py: detects surface spills and publishes the relevant topics
    training_visualization.py: visualizes the training data and publishes the relevant topics
    calibration_controller.py: calibrates the camera to the robot base and publishes the relevant topics
    training_controller.py: records training data and publishes the relevant topics
    playback_controller.py: replays training data and publishes the relevant topics

### Launch List
calibration.launch.py: launches the calibration_controller node, urobot_driver, and the zed_driver node
training.launch.py: launches the training_controller node, the zed_driver node, and the force_sensor_driver node
playback.launch.py: launches the playback_controller node, the urobot_driver node, zed driver, visualization node
